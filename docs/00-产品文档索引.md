## 产品一句话

「猫吃了吗」不是猫罐头百科，也不是精细喂养日志，而是一个面向挑食猫主人的轻量试吃记忆与补货判断工具。

它用“拍一下包装 + 点一下猫的真实行为”，帮助用户记住：

- 哪款值得再给机会；
- 哪款已经稳定通过验证；
- 哪款以前喜欢、最近却变了；
- 哪款应该只清库存或彻底避雷；
- 下次补货时应该优先找哪些产品。

## 本轮已经形成的核心共识

### 已确定

- 用户喜欢尝试新品，但不喜欢持续填写复杂记录。
- 海外罐头品牌、系列、口味和质地很多，仅凭记忆容易混淆。
- 购买渠道和低价车经常变化，因此产品不应依赖固定商品链接。
- 同一款罐头只需首次拍照建档，再次试吃不重复拍摄。
- 判断依据应优先记录猫的行为，而不是精确计算吃了多少克。
- 一款新品在滚动 90 天内累计获得 3 次正向反馈后，可进入长期回购清单。
- 首页第一优先级是“立即记录”，状态概览和补货判断下沉。
- 当前结论只计算滚动 90 天内的有效反馈；完整历史永久保留。
- “埋屎拒绝”会进入避雷，但用户可以手动选择“再给一次机会”。
- 食物需要区分主食罐头、零食罐头、冻干、猫条、猫粮和其他类型。
- 当前版本只支持单猫，暂不设计多猫切换和反馈归属。
- 包装识别是确定需要的效率能力，先保留人工确认与失败回退。
- 猫的偏好会变化，历史喜欢不能永久代表现在喜欢。
- 补货通常发生在现有库存接近吃完时，而不是每次吃完立即购买。

### 当前产品假设

- 用户愿意在一次喂食后完成一个约 3–10 秒的反馈动作。
- “主动吃 / 正常接受 / 勉强吃 / 埋屎拒绝 / 没法判断”足够覆盖首版判断。
- 用户补货时，比起查看完整历史，更需要直接看到“放心买、少量再试、待复验、近期观察、不主动补货、埋屎避雷”。
- 可添加到手机桌面的 H5 / PWA 更适合先验证个人是否会持续记录，并方便用邀请链接给少量测试者体验。

### 本轮已确认的产品决策

| 编号 | 决策 | 产品处理 |
|---|---|---|
| D-001 | 首页首要任务是立即记录 | 首页首屏先展示“立即记录”，包含“拍新品”和“记录已有食物”两个入口 |
| D-002 | 三次正向反馈增加 3 个月范围 | 使用滚动 90 天窗口计算当前结论；历史记录不删除 |
| D-003 | 埋屎拒绝允许手动再试 | 避雷详情中提供“再给一次机会”，不自动抹掉原记录 |
| D-004 | 需要区分食物类型 | 预置主食罐头、零食罐头、冻干、猫条、猫粮、其他 |
| D-005 | 暂不支持多猫 | 当前数据和反馈均默认属于同一只猫，不出现猫档案与切换入口 |
| D-006 | 需要包装识别 | 拍照后给出品牌、名称、类型、口味等建议，用户确认后保存；失败时可手填 |
| D-007 | 首版改为 H5 / PWA | 先绕开小程序上架流程验证使用习惯；稳定使用后再评估迁移 |
| D-008 | 底部导航只负责页面到达 | “立即记录”进入独立一级页面；首页仍保留单手可触达的两个直接入口 |

### 仍需后续验证

- “主动吃”和“正常接受”是否需要不同权重。
- 长期回购款出现一次“勉强吃”时，是否应立即进入近期观察。
- 包装识别首版能够稳定识别哪些字段，是否要同时承担同款查重。
- 90 天窗口是否适合真实轮换周期，还是需要由用户自行调整。

## 用文档调整 UI 的方法

不要先讨论某个卡片圆角或图标大小，先判断页面任务。

| 如果你认为…… | UI 应该优先调整…… |
|---|---|
| 首页主要用于快速记一笔（已确认） | 缩小展示型 Hero，把“立即记录”变成第一主模块 |
| 首页用于了解当前情况 | 状态总览保留，但放在立即记录之后 |
| 新品建档是最大阻力 | 首页突出拍照；表单字段继续减少 |
| 用户最怕忘记买什么 | 补货清单强化检索和识别，但仍排在立即记录之后 |
| 猫的口味变化最重要 | 首页应突出“近期降温”和变化提醒 |
| 产品要更像生活工具 | 减少装饰面积，提高真实罐头照片占比 |
| 产品要更像有性格的品牌 | 保留猫角色，用低饱和彩色弥散建立识别，不依赖厚重强色块 |

## 当前实现与文档关系

- 当前 H5 已经跑通新品建档、食物类型、行为反馈、90 天状态推导、手动再试、详情历史和补货分组。
- D-001 至 D-005、D-007 与 D-008 已进入当前 H5；D-006 包装识别仍是下一阶段能力。
- 文档描述的是产品意图；如果已确认规则与当前实现冲突，以产品决策为目标、分批修改代码。
- 本轮不把后续设想自动加入开发范围，避免首版重新膨胀。
