# 「猫吃了吗」PRD：产品需求文档

> 版本：v0.3 可用原型稿  
> 日期：2026-07-28  
> 当前阶段：单猫、单设备、H5 / PWA MVP

## 1. 产品概述

「猫吃了吗」帮助挑食猫主人用最低记录成本建立个人试吃档案，并在补货前得到基于真实历史的购买建议。

### 核心闭环

1. 首次尝试：拍包装，由系统识别基础信息并由用户确认。
2. 吃过之后：选择最接近的行为反馈。
3. 再次尝试：从原档案继续反馈，不重复拍照。
4. 系统判断：根据多次反馈更新状态。
5. 补货之前：查看放心买、少量再试、观察、清库存和避雷清单。

## 2. 产品目标

### 用户目标

- 10 秒内记住一次试吃表现；
- 打开首页后能立即开始记录，不先阅读状态面板；
- 下次看到同款时能认出来；
- 补货时不用重新翻购买记录和回忆；
- 保留猫偏好随时间变化的事实；
- 减少无效尝试和重复踩雷。

### 产品目标

- 验证用户是否愿意为同一款持续记录；
- 验证状态规则能否帮助真实补货；
- 建立可扩展的食物—反馈—状态数据结构；
- 用最小页面集合跑通完整闭环。

## 3. 非目标

首版明确不做：

- 固定商品链接或自动回购；
- 价格监控、优惠车聚合和比价；
- 精确库存扣减；
- 营养分析、热量计算或医疗建议；
- 品牌公共评分和社区种草；
- 全量海外罐头商品库；
- 自动推断过敏或健康问题；
- 多猫档案、多成员共享；
- 复杂提醒和连续打卡体系。

## 4. 用户与使用场景

### 主用户

单猫家庭中的主要喂养者，愿意尝试新品，但不喜欢复杂记录。

### 场景 A：首次尝试新品

- 用户拿出一款此前没有记录过的罐头；
- 拍摄包装；
- 系统尝试识别食物类型、品牌、名称、肉源、质地和国家；
- 用户确认或修改识别结果，也可以在识别失败时手动填写；
- 保存后进入详情；
- 吃过后再补一次行为反馈。

### 场景 B：再次打开同款

- 用户从首页、最近尝过、观察中或搜索进入详情；
- 直接记录这次表现；
- 不重新拍包装，不重复填写基础信息。

### 场景 C：补货前筛选

- 现有库存即将吃完；
- 用户打开补货清单；
- 优先查看“放心买”和“少量再试”；
- 根据当前渠道自行找车，不依赖历史链接。

### 场景 D：以前喜欢，现在不喜欢

- 已经进入长期回购的产品出现负反馈；
- 状态进入“近期观察”；
- 历史正向记录仍然保留；
- 如果再次接受，且近 90 天正向累计仍达到 3 次，则恢复长期回购；否则进入待复验；
- 如果连续多次负反馈，提示用户手动暂停。

### 场景 E：埋屎后仍想再试

- 新品因一次“埋屎拒绝”进入避雷；
- 用户根据剩余库存或当时状态，手动选择“再给一次机会”；
- 原埋屎记录继续保留，当前状态回到试吃中；
- 下一次真实反馈重新决定它进入试吃、清库存或避雷。

## 5. MVP 范围

### P0：首版必须

- 拍照或相册选择包装；
- 预置食物类型：主食罐头、零食罐头、冻干、猫条、猫粮、其他；
- 新建、编辑、删除食物档案；
- 五种行为反馈；
- 食物详情及反馈历史；
- 自动状态推导；
- 首页以“立即记录”为首要模块；
- 独立“立即记录”一级页面，承接新品和已有食物两条记录路径；
- 90 天滚动反馈窗口；
- 埋屎避雷后手动“再给一次机会”；
- 首页观察对象和最近记录；
- 补货清单分组；
- 关键词搜索；
- 浏览器本地存储；
- PWA Manifest 与离线缓存；
- 示例数据入口。

### P1：验证后优先

- 包装 OCR / 图像识别，并由用户确认结果；
- 同款重复建档提醒；
- 更清楚的待反馈入口；
- 自定义食物类型和类型管理；
- 数据导出与备份；
- 邀请码匿名身份与云端同步。

P0 可在没有自动识别的情况下通过“照片 + 手填”完成闭环；包装识别已经确定需要，但不应阻塞其他已验证功能发布。

### P2：后续探索

- 家庭成员共享；
- 订阅提醒；
- 趋势与偏好分析；
- 可选购买渠道备注；
- 公开商品资料补全。

## 6. 核心规则

### 6.1 反馈选项

| Key | 用户文案 | 定义 | 是否计入有效判断 | 分值仅供理解 |
|---|---|---|---|---:|
| eager | 主动吃 | 闻到就吃，明显有兴趣 | 是，正向 | +2 |
| okay | 正常接受 | 会自己吃，没有特别兴奋 | 是，正向 | +1 |
| reluctant | 勉强吃 | 饿了才吃，或需要加料 | 是，负向 | -1 |
| bury | 埋屎拒绝 | 闻完就走，并出现埋屎动作 | 是，强负向 | -2 |
| unknown | 没法判断 | 当天整体食欲或状态特殊 | 否 | 0 |

首版实际状态规则不直接累加分值，而是使用反馈类型、正向次数和近期连续负反馈。

### 6.2 状态定义

| 状态 | 触发条件 | 补货分组 | 用户含义 |
|---|---|---|---|
| 试吃中 | 尚未满足其他条件 | 少量再试 | 继续少量尝试 |
| 长期回购 | 滚动 90 天内累计至少 3 次正向，且近期无负反馈 | 放心买 | 当前仍可纳入常备候选 |
| 待复验 | 曾经进入长期回购，但滚动 90 天内已不足 3 次正向，且无近期负反馈 | 待复验 | 历史表现好，但现在需要重新确认 |
| 近期观察 | 曾经通过 3 次正向，但 90 天内最新连续记录中存在负向 | 近期观察 | 以前喜欢，最近降温 |
| 只清库存 | 尚未长期通过，最新反馈为勉强吃 | 不主动补货 | 现有库存可慢慢吃 |
| 埋屎避雷 | 尚未长期通过，最新反馈为埋屎拒绝，且用户未选择再试 | 埋屎避雷 | 默认不要再买，但可手动再给机会 |
| 暂停回购 | 用户手动暂停 | 不主动补货 | 保留历史，但暂不购买 |

### 6.3 状态转换

- `主动吃`与`正常接受`均计为一次正向反馈。
- 当前状态只计算滚动 90 天内的有效反馈；90 天以前的记录继续保留在历史中。
- 90 天内正向反馈累计达到 3 次即可进入长期回购，不要求连续。
- 一款食物一旦进入过长期回购，需保留`everQualified`，用于在窗口过期后显示“待复验”，而不是伪装成从未验证。
- `没法判断`保留记录，但不影响状态。
- 尚未通过长期回购时：
  - 最新为`勉强吃` → 只清库存；
  - 最新为`埋屎拒绝` → 埋屎避雷；
  - 最新为正向 → 继续试吃。
- 已通过长期回购后：
  - 出现近期负反馈 → 近期观察；
  - 再次出现正向反馈，且近 90 天累计仍达到 3 次 → 恢复长期回购；
  - 再次出现正向反馈，但近 90 天累计不足 3 次 → 待复验。
- 曾经通过长期回购，但滚动 90 天内正向反馈不足 3 次且没有近期负反馈 → 待复验。
- 近期连续 3 次负反馈时，只提示暂停，不自动删除或永久淘汰。
- 埋屎避雷不是永久删除：
  - 用户可在详情页选择“再给一次机会”；
  - 操作后写入`manualRetryAfter`，保留埋屎历史，状态回到试吃中；
  - 在产生下一次反馈前，刚被手动放行的埋屎记录不再把状态立即推回避雷；
  - 如果下一次仍为埋屎拒绝，再次进入埋屎避雷；
  - 如果下一次为勉强吃，进入只清库存；
  - 如果下一次为正向，按滚动 90 天进度继续试吃。
- 用户手动暂停后，新一次真实反馈会解除手动暂停，并重新按规则判断。

### 6.4 规则口径

- “3 个月”在程序中按滚动 90 天计算，以当前时间向前回溯。
- 时间窗口影响当前状态和回购进度，不删除历史反馈。
- 窗口跨越时状态可自动从长期回购变为待复验，无需用户操作。
- `everQualified`不等于当前放心买，只表示历史上曾经达到过标准。

### 6.5 仍需验证

- “主动吃”和“正常接受”是否应该具有不同权重？
- 长期回购款一次勉强吃是否应该立即进入观察？
- 连续负反馈是否应包含“勉强 + 埋屎”的混合组合？

## 7. 功能需求

### 7.1 首页

#### 目标

让用户打开后立即开始记录；状态概览只承担次要辅助作用。

#### 信息

- 紧凑的产品名称与档案入口；
- 首屏下半区固定“立即记录”主模块；
- “拍新品”和“记录已有食物”两个并列动作；
- 放心买、观察中等数量概况；
- 最多 5 款最近尝过的横向卡片；默认视窗露出 2 张完整卡片和约 0.3 张下一张卡片；
- 空状态与示例数据入口。

#### 交互

- 点击拍新品 → 新建页；
- 点击记录已有食物 → 最近食物选择层；选中后进入反馈页；
- 没有已有食物时，“记录已有食物”转为引导新建；
- 点击食物卡 → 详情页；
- 点击补货相关入口 → 补货清单。
- 点击底部“立即记录” → 进入独立记录页，而不是直接弹出选择层。

#### 布局优先级

1. 立即记录；
2. 最近可记录的食物；
3. 当前观察与待复验；
4. 补货摘要；
5. 品牌装饰。

展示型 Hero 应缩小，不得把主动作推到首屏以下。

### 7.1.1 立即记录页

#### 目标

把底部“立即记录”定义为稳定的一级目的地，而不是伪装成导航的一次性动作；用户进入后仍能清楚选择“拍新品”或“记录已有食物”。

#### 信息与交互

- 顶部并列展示“拍一款新品”和“记录已有食物”两条路径；
- 新品入口直接进入新建页；
- 已有食物入口打开最近食物选择层；
- 下方展示最近吃过的最多 5 款食物，点击后直接进入该食物的反馈页；
- 没有食物时展示猫猫头空状态，并引导先拍新品；
- 页面保留底部导航，当前项为“立即记录”。

### 7.2 新建/编辑页

#### 必填规则

必须选择食物类型，并满足以下任意一个身份条件即可保存：

- 已选择包装照片；
- 已填写名称；
- 已填写品牌。

#### 字段

| 字段 | 类型 | 是否必填 | 默认值 |
|---|---|---|---|
| 包装照片 | 拍照/相册 | 条件必填 | 无 |
| 食物类型 | 单选 | 是 | 无；识别成功时预填 |
| 品牌 | 文本 | 否 | 待补充品牌 |
| 系列或名称 | 文本 | 否 | 未命名新品 |
| 口味/肉源 | 文本 | 否 | 口味待确认 |
| 质地 | 单选 | 否 | 肉泥/慕斯 |
| 国家 | 文本 | 否 | 空 |
| 试买数量 | 单选 | 否 | 1 罐 |

#### 保存后

- 新建成功 → 详情页；
- 编辑成功 → 详情页；
- 照片压缩后保存在浏览器本地数据中；
- 不要求用户立即反馈。

#### 食物类型

- 预置：主食罐头、零食罐头、冻干、猫条、猫粮、其他；
- 卡片和详情均需显示；
- 补货清单可按类型筛选，但仍以回购结论作为第一分组；
- 自定义类型不进入当前 P0。

#### 包装识别

- 用户拍照或选择相册图片后自动开始；
- 建议输出食物类型、品牌、名称、口味/肉源、质地和国家；
- 所有识别字段都必须允许修改，保存前由用户确认；
- 识别失败、超时或无网络时，保留照片并直接进入手动填写，不阻塞建档；
- 识别结果如疑似命中已有档案，优先提示用户进入原档案，避免重复创建。

### 7.3 反馈页

#### 目标

用一次选择记录猫的行为，不要求用户估算精确摄入量。

#### 规则

- 未选择反馈时，提交按钮禁用；
- 选择`勉强吃`后，可选补充：
  - 饿了才吃；
  - 加冻干才吃；
  - 拌着才吃；
- 备注最多 120 字；
- 提交后显示状态相关提示，并回到详情；
- 同一次提交不可重复触发。

### 7.4 详情页

#### 信息

- 包装照片或默认罐头图标；
- 品牌、名称、肉源、质地、国家、试买数量；
- 当前状态；
- 近 90 天回购进度；
- 状态解释；
- 按时间倒序的反馈历史；
- 编辑、记录、暂停/恢复、删除操作；
- 埋屎避雷状态下显示“再给一次机会”。

#### 危险操作

- 删除前必须二次确认；
- 删除会同时删除全部反馈，当前不可恢复。

### 7.5 补货清单

#### 单猫信息

- 页面顶部使用独立浅色彩色弥散资料区，居中展示大尺寸猫咪头像和年龄；下方补货内容以顶部大圆角半透明浅色面板承接；
- 视觉采用接近 iOS 的轻盈层次：彩色只出现在低饱和背景光晕与关键选中态，内容层使用半透明白、细描边和克制阴影，不使用厚重深色大底；
- 资料区同时显示“吃过款数”和“放心买款数”，帮助用户快速感知当前档案规模；
- 首版仍只支持一只猫，不出现猫咪切换入口；
- 年龄可在当前页轻量编辑；未填写时明确显示“年龄待补充”，不使用虚构默认值；
- 头像可以从相册替换；未上传时使用产品内置的真实猫咪默认头像。

#### 状态 Tab 顺序

1. 放心买；
2. 少量再试；
3. 待复验；
4. 近期观察；
5. 不主动补货；
6. 埋屎避雷。

仅展示当前搜索结果中有内容的状态 Tab，默认选中顺序最靠前的有内容状态。

#### 食物类型筛选

- 类型顺序固定为：主食罐头、零食罐头、冻干、猫条、猫粮、其他；
- 类型以当前状态 Tab 下的线框胶囊展示；
- 只有当前状态下存在对应食物时，才展示该类型胶囊；
- 默认不选中任何胶囊，等同于展示当前状态下的全部类型；
- 点击具体类型后加强描边和文字颜色，不使用大面积填色；
- 再次点击已选类型可取消筛选并恢复全部。

#### 搜索范围

- 品牌；
- 名称；
- 口味/肉源；
- 质地；
- 食物类型；
- 国家。

#### 规则

- 食物有真实包装照片时优先显示照片；
- 主食罐头和零食罐头没有照片或图片加载失败时，使用罐头线描图标兜底；其他食物使用通用包装图标；
- 猫猫头像只属于顶部猫咪资料，不作为补货商品的缺图占位；
- 只展示有内容的状态 Tab；
- 搜索后同步更新总数和放心买数量；
- 点击食物进入详情；
- 不提供购买链接和价格。

## 8. 数据模型

### Food

```js
{
  id: String,
  name: String,
  brand: String,
  foodType: "staple_can" | "snack_can" | "freeze_dried" | "cat_treat" | "cat_food" | "other",
  flavor: String,
  texture: String,
  country: String,
  photoPath: String,
  quantityBought: Number,
  color: String,
  createdAt: Number,
  manualStatus: String | null,
  manualRetryAfter: Number | null,
  everQualified: Boolean | undefined,
  results: Result[]
}
```

### Result

```js
{
  id: String,
  outcome: "eager" | "okay" | "reluctant" | "bury" | "unknown",
  assistedBy: String,
  note: String,
  createdAt: Number
}
```

### 派生字段

- `positiveCount`
- `positiveCount90d`
- `recentNegativeCount`
- `lastEffectiveAt`
- `isStale`
- `status`
- `latestResult`
- `latestOutcome`
- `progress`
- `shouldSuggestPause`

派生字段不直接持久化，读取时根据原始反馈重新计算。

## 9. 空、错与边界状态

| 场景 | 处理 |
|---|---|
| 首次打开无数据 | 展示空状态，可新建或加载示例 |
| 没有已有食物 | “记录已有食物”转去新建 |
| 找不到指定食物 | Toast 提示并返回 |
| 拍照失败/取消 | 停留当前页面，不生成空记录 |
| 照片持久化失败 | 尝试使用临时路径，不阻塞建档 |
| 搜索无结果 | 区分“尚无数据”和“关键词未命中” |
| 当天整体食欲异常 | 允许选择“没法判断” |
| 包装识别失败或超时 | 保留照片并允许手动填写，不阻塞保存 |
| 曾经回购但 90 天内记录不足 | 自动显示“待复验”，不删除历史资格 |
| 删除后返回 | 回到首页，列表刷新 |

## 10. 数据与隐私

- P0 数据仅保存在当前浏览器；
- 包装照片压缩后随食物档案保存在本地；
- 不采集用户身份、地理位置或健康信息；
- 卸载、清理缓存或换设备可能导致数据丢失；
- P1 接入包装识别时，需明确告知图片会被上传处理，并补充服务方、保存期限、删除策略和失败回退；
- 接入云同步前需要补充隐私政策、数据迁移和账号体系方案。

## 11. 成功指标与事件建议

### 核心成功指标

同一款食物产生第 2 次有效反馈的比例。

理由：只有发生二次反馈，产品才真正从“收藏夹”变成动态判断工具。

### 建议事件

- `food_create_started`
- `food_created`
- `food_recognition_started`
- `food_recognition_confirmed`
- `food_recognition_failed`
- `food_detail_viewed`
- `feedback_started`
- `feedback_submitted`
- `food_qualified`
- `food_entered_observe`
- `library_viewed`
- `library_searched`
- `food_paused`
- `food_retry_after_bury`
- `food_deleted`

首版可以暂不接埋点，但事件命名可作为后续数据方案基础。

## 12. 发布验收标准

- 新用户能在无说明情况下完成一次建档；
- 同款可以从详情再次反馈，不重复拍照；
- 五种反馈均正确生成历史记录；
- 状态转换符合单元测试；
- 首页首屏第一任务为“立即记录”；
- 底部三个入口均为可返回、可刷新、可分享 URL 的页面目的地；
- “立即记录”页能分别进入新品建档和已有食物反馈；
- 底部导航内容区不低于 48px，并叠加设备底部安全区；
- 图标采用统一的 24px 线描体系；食物照片缺失或加载失败时使用猫猫头兜底；
- 90 天窗口过期后正确进入“待复验”；
- 埋屎避雷可以手动再给一次机会，且原反馈不丢失；
- 食物类型可录入、展示和筛选；
- 补货清单分组正确；
- 删除需要确认；
- 页面空状态可理解；
- WXML/WXSS 编译通过；
- 核心规则自动测试全部通过；
- 浏览器预览无阻塞性错误。

## 13. 本轮产品决策

1. 首页第一任务确定为“立即记录”。
2. 长期回购需在滚动 90 天内累计 3 次正向反馈。
3. 埋屎拒绝进入避雷，但支持用户手动再给一次机会。
4. 需要区分主食罐头、零食罐头、冻干、猫条、猫粮和其他。
5. 当前明确只支持单猫。
6. 包装识别确定需要，列为 P1 第一优先能力，所有结果均需用户确认。
7. 底部“立即记录”升级为一级页面；首页仍保留单手可触达的两个直接入口。
8. 全应用采用轻盈、接近 iOS 的视觉语言：`#FAFAFA` 画布、低饱和彩色弥散、半透明白表面、细描边和克制阴影；品牌绿只用于正向状态、选中态与关键提交，系统蓝用于普通编辑和拍照动作。
9. 继续以 DDMC 的间距、触控和 1.5px 线描图标规则为基础约束，但不照搬生鲜业务外观。

尚待后续验证：两种正向反馈是否加权、负反馈进入观察的敏感度，以及包装识别首版字段准确率。
